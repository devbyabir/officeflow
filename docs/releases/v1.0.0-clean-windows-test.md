# OfficeFlow: clean Windows release checks

Use a disposable Windows 11 x64 machine and fictional data. The automated
Windows workflow tests installation, the hidden launcher, first-run setup,
restart, upgrade, uninstall, the portable ZIP, and checksums. These remaining
checks need a normal browser download on a clean client machine.

| Check | Status | What to verify |
| --- | --- | --- |
| Missing Visual C++ runtime | Pending | Setup offers Microsoft's official x64 redistributable; the launcher gives a useful message if it is still missing. |
| Smart App Control On | Pending trusted signing | Download the signed installer and ZIP in a browser. Installer, launcher, and uninstaller must all open without a Code Integrity block. |
| First-run account and recovery | Pending clean client | Choose a username, a 6–12 character password and a hint. Save the recovery code. Restart, log in, view the hint, and use the code once to reset the password. The old code must fail afterward. |

The currently published 1.0.0 installer is unsigned. Smart App Control may
block it with an unverified publisher message. This cannot be verified as fixed
until the release binaries are signed with a trusted publisher identity and
tested on a Windows 11 machine with Smart App Control On. A SHA-256 checksum
proves file integrity; it does not establish a trusted publisher.

For each downloaded file, compare PowerShell's `Get-FileHash -Algorithm SHA256`
output with its `.sha256` release asset. Record the Windows build, Smart App
Control state, OfficeFlow version, signature status from `Get-AuthenticodeSignature`,
and the result of each action. Do not switch off Smart App Control to claim a pass.
