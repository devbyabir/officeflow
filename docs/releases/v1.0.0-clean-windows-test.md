# OfficeFlow 1.0.0: clean Windows test (missing Visual C++ runtime)

**Status: PENDING.** This test needs a disposable Windows 10 or 11 x64 machine
without the Microsoft Visual C++ Redistributable. GitHub's hosted Windows
runners always have the runtime (Windows kept its DLLs even after Microsoft's
uninstallers ran), and no disposable Windows 10/11 VM was available on the
review PC: Windows Sandbox and Hyper-V are not installed, and virtualization is
off in the firmware. The rest of the ZIP flow (first launch, restart,
replacement copy, no Microsoft files in the ZIP) passes in CI on Windows Server
2025.

## What this test proves

1. The Visual C++ runtime is absent before launching.
2. `Start OfficeFlow.cmd` shows the prerequisite message, opens Microsoft's
   official page and does not start OfficeFlow or create a workspace.
3. After installing Microsoft's x64 runtime, the same ZIP starts, and a test
   record survives a restart and a replacement copy.

## You need

- A **fresh, disposable** Windows 10 or 11 x64 VM or PC with internet access.
  Windows Sandbox on Windows 10/11 Pro works after enabling the "Windows
  Sandbox" optional feature and restarting. It starts clean each time and
  discards everything when closed.
- The exact draft ZIP from the draft release `v1.0.0` (sign in to GitHub as the
  owner): `OfficeFlow-1.0.0-windows-x64.zip` and its `.sha256` file. Write down
  the SHA-256 from the `.sha256` file.

Use only fictional test data. Run the PowerShell commands in **Windows
PowerShell** inside the VM.

## Steps

### 1. Check the download

```powershell
Get-FileHash "$env:USERPROFILE\Downloads\OfficeFlow-1.0.0-windows-x64.zip"
```

The hash must equal the one in `OfficeFlow-1.0.0-windows-x64.zip.sha256`.

### 2. Confirm the Visual C++ runtime is absent

```powershell
"vcruntime140.dll","vcruntime140_1.dll","msvcp140.dll" | ForEach-Object {
  $p = Join-Path $env:SystemRoot "System32\$_"
  if (Test-Path $p) { "$_ PRESENT $((Get-Item $p).VersionInfo.FileVersion)" } else { "$_ absent" }
}
Test-Path 'HKLM:\SOFTWARE\Microsoft\VisualStudio\14.0\VC\Runtimes\x64'
```

Expected: all three are `absent`, and the last line prints `False`. If any is
present, this machine is not suitable; use a fresh one.

### 3. Extract into a folder with spaces

```powershell
$folder = "$env:USERPROFILE\Documents\OfficeFlow clean test"
Expand-Archive "$env:USERPROFILE\Downloads\OfficeFlow-1.0.0-windows-x64.zip" $folder
explorer "$folder\OfficeFlow-1.0.0-windows-x64"
```

### 4. Missing-runtime launch

Double-click **Start OfficeFlow.cmd**. Allow it to run if SmartScreen asks.

Expected:

- The window says *OfficeFlow needs the Microsoft Visual C++ Redistributable
  for Visual Studio 2015-2022 (x64), version 14.40 or newer* and
  *vcruntime140.dll is not installed.*
- The browser opens
  https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist.
- No admin-password prompt appears, and OfficeFlow does not start.
- Then confirm nothing was created:

  ```powershell
  Test-Path "$env:LOCALAPPDATA\OfficeFlow"   # expected: False
  ```

Press a key to close the window.

### 5. Install the official x64 runtime

On the Microsoft page that opened, download the **X64** redistributable
(`vc_redist.x64.exe`). Then check its signature and install it:

```powershell
$installer = "$env:USERPROFILE\Downloads\vc_redist.x64.exe"
(Get-AuthenticodeSignature $installer) | Format-List Status, SignerCertificate
Start-Process $installer -ArgumentList "/install", "/passive", "/norestart" -Wait
"vcruntime140.dll","vcruntime140_1.dll","msvcp140.dll" | ForEach-Object {
  "$_ $((Get-Item (Join-Path $env:SystemRoot "System32\$_")).VersionInfo.FileVersion)"
}
```

Expected: `Valid`, signed by Microsoft Corporation, and all three files 14.40 or
newer.

### 6. First launch with the same ZIP

Double-click **Start OfficeFlow.cmd** again.

1. Choose a test admin password (12–120 characters) and type it twice.
2. The browser opens http://127.0.0.1:8080. Sign in as `001`.
3. Under **Supply inventory**, add the supply `Clean VM check paper`,
   quantity `5`.
4. In the OfficeFlow window, press `Ctrl+C`, then `Y`.

```powershell
Test-Path "$env:LOCALAPPDATA\OfficeFlow\officeflow.mv.db"   # expected: True
```

### 7. Restart

Double-click **Start OfficeFlow.cmd**, sign in as `001` and confirm that
`Clean VM check paper` (5) is listed. Stop with `Ctrl+C`, then `Y`.

### 8. Replacement copy

```powershell
Expand-Archive "$env:USERPROFILE\Downloads\OfficeFlow-1.0.0-windows-x64.zip" "$env:USERPROFILE\Documents\OfficeFlow replacement"
```

Start **Start OfficeFlow.cmd** from the new folder. Sign in and confirm
`Clean VM check paper` is still listed. Stop OfficeFlow, then discard the VM.
