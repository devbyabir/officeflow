# OfficeFlow 1.0.0: clean Windows tests

Two manual tests remain before release. Both need a real Windows 11 (or 10) x64
machine; GitHub's hosted runners cannot do them.

| Test | Status | Why it is manual |
| --- | --- | --- |
| A. Missing Visual C++ runtime | **PENDING** | Hosted runners always have the runtime; no disposable Windows 10/11 VM was available on the review PC (Windows Sandbox and Hyper-V not installed, virtualization off in the firmware). |
| B. Smart App Control, signed build | **PENDING** (needs the signed build) | The draft build's `OfficeFlow.exe` is not signed yet, so Smart App Control blocks it. |

The rest of the ZIP flow passes in CI on Windows Server 2025: first run with the
password prompt, restart, second launch, a replaced and a second extracted copy
opening the same workspace, no script launchers, no Microsoft runtime files, and
`OfficeFlow.exe` starting only the bundled `java.exe`.

Use only fictional test data. Run the PowerShell commands in **Windows
PowerShell** on the test machine.

## Common steps

1. Download `OfficeFlow-1.0.0-windows-x64.zip` and its `.sha256` file from the
   draft release `v1.0.0` **with a web browser** (sign in to GitHub as the
   owner), into `Downloads`.
2. Check the hash; it must equal the one in the `.sha256` file:

   ```powershell
   Get-FileHash "$env:USERPROFILE\Downloads\OfficeFlow-1.0.0-windows-x64.zip"
   ```

3. Extract it normally (right-click → **Extract All**) to
   `Documents\OfficeFlow clean test`. Do not unblock the ZIP or change any
   security setting.

## Test A: missing Visual C++ runtime

Needs a **fresh, disposable** Windows 10/11 x64 machine without the runtime,
for example Windows Sandbox (Windows 10/11 Pro, "Windows Sandbox" optional
feature). With the unsigned draft build, use a machine where Smart App Control
is not on (Windows Sandbox does not run it); with the signed build, Smart App
Control can stay on.

1. Confirm the runtime is absent:

   ```powershell
   "vcruntime140.dll","vcruntime140_1.dll","msvcp140.dll" | ForEach-Object {
     $p = Join-Path $env:SystemRoot "System32\$_"
     if (Test-Path $p) { "$_ PRESENT $((Get-Item $p).VersionInfo.FileVersion)" } else { "$_ absent" }
   }
   Test-Path 'HKLM:\SOFTWARE\Microsoft\VisualStudio\14.0\VC\Runtimes\x64'
   ```

   Expected: all three `absent`, and `False`. Otherwise use a fresh machine.
2. Double-click **OfficeFlow.exe**. Expected: the window says *OfficeFlow needs
   the Microsoft Visual C++ Redistributable for Visual Studio 2015-2022 (x64),
   version 14.40 or newer* and *vcruntime140.dll is not installed.*; the browser
   opens https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist;
   there is no password prompt and OfficeFlow does not start;
   `Test-Path "$env:LOCALAPPDATA\OfficeFlow"` prints `False`. Press Enter to close.
3. On that Microsoft page, download the **X64** `vc_redist.x64.exe`, check that
   it is signed by Microsoft Corporation, and install it:

   ```powershell
   $installer = "$env:USERPROFILE\Downloads\vc_redist.x64.exe"
   (Get-AuthenticodeSignature $installer) | Format-List Status, SignerCertificate
   Start-Process $installer -ArgumentList "/install", "/passive", "/norestart" -Wait
   ```

4. Continue with **Workspace checks** below.

An outdated runtime (older than 14.40) shows the same message with the file's
version. It needs a machine with an old runtime and is not covered by these steps.

## Test B: Smart App Control with the signed build

Needs Windows 11 with Smart App Control **On** (Settings → Privacy & security →
Windows Security → App & browser control → Smart App Control) and the x64
Visual C++ runtime installed.

1. Check the signature of the extracted launcher:

   ```powershell
   Get-AuthenticodeSignature "$env:USERPROFILE\Documents\OfficeFlow clean test\OfficeFlow-1.0.0-windows-x64\OfficeFlow.exe" |
     Format-List Status, SignerCertificate, TimeStamperCertificate
   ```

   Expected: `Valid`, with the expected publisher and a timestamp.
2. Note the time, then continue with **Workspace checks**.
3. Afterwards, confirm Smart App Control blocked nothing:

   ```powershell
   Get-WinEvent -FilterHashtable @{ LogName = 'Microsoft-Windows-CodeIntegrity/Operational'; StartTime = (Get-Date).AddHours(-1) } |
     Where-Object { $_.Id -in 3077, 3118 } | Format-List TimeCreated, Id, Message
   ```

   Expected: no events.

## Workspace checks (both tests)

1. Double-click **OfficeFlow.exe**. Choose a test admin password (12–120
   characters) and type it twice; typing is hidden.
2. The browser opens http://127.0.0.1:8080. Sign in as `001` and add the supply
   `Clean VM check paper`, quantity `5`.
3. Close the OfficeFlow window (or press `Ctrl+C` in it).
   `Test-Path "$env:LOCALAPPDATA\OfficeFlow\officeflow.mv.db"` prints `True`.
4. Double-click **OfficeFlow.exe** again: no password prompt; sign in and
   confirm `Clean VM check paper` (5) is listed. Close OfficeFlow.
5. Delete the extracted folder, extract the ZIP again (normally), start
   **OfficeFlow.exe** and confirm the supply is still listed. Close OfficeFlow.
